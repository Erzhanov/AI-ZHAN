# AIZHAN — медициналық AI көмекші

**Денсаулық туралы сұрақтарға Қазақстан Республикасының клиникалық хаттамаларына сүйеніп жауап беретін платформа.**

AIZHAN пайдаланушының шағымын нақтылауға, талдау нәтижелеріне қатысты хаттамалық ақпаратты табуға және медициналық құжаттарды түсінуге көмектеседі. Жауаппен бірге пайдаланылған хаттаманың бастапқы сілтемесі беріледі.

> AIZHAN — ақпараттық көмекші. Чаттағы жауап диагнозды растамайды және дәрігердің тексеруі мен ем тағайындауын алмастырмайды.

## Мүмкіндіктері

- **Медициналық чат:** шағым мен әңгімедегі бұрынғы жауаптарды ескереді.
- **Нақтылау сұрақтары:** бір жауапта ең көбі екі сұрақ; маңызды мәліметтерді анықтауға бағытталған.
- **Хаттамалық іздеу:** MedElement экспортындағы JSONL мәтіндерінен тиісті бөлімдерді іздейді.
- **Талдаулар туралы ақпарат:** көрсеткіш, мәні, өлшем бірлігі және зертхана нормасы бойынша қатысты хаттама бөлімдерін табуға көмектеседі.
- **Дереккөздер:** жауапта нақты пайдаланылған хаттамаларға сілтемелер көрсетіледі.
- **Тілдер:** интерфейс қазақша және орысша; медициналық жауаптарда қазақша, орысша және ағылшынша өңдеу бар.
- **Жеке кабинет:** профиль, сақталған сұрақтар тарихы және Pro жазылымының күйі.
- **Әкімші панелі:** қолдану көрсеткіштері, чаттар және медициналық жауапты тексеру журналы.
- **Бейімделген дизайн:** телефон мен компьютерге арналған интерфейс, Motion анимациялары және қозғалысты азайту баптауын қолдау.

## AI қалай жұмыс істейді?

1. Пайдаланушы сұрағы мен бұрынғы жауаптар талданады. Хабарланған, жоққа шығарылған және белгісіз мәліметтер ажыратылады.
2. Қауіпті белгілер тексеріледі. Шұғыл белгі анықталса, жүйе сауалнама мен хаттама іздеуді күтпей көмекке жүгінуді ұсынады.
3. Жалпы хаттамалық сұраққа жеке сауалнама талап етілмейді. Жеке шағым үшін қажетті мәлімет жетіспесе, нақтылау сұрақтары қойылады.
4. Симптом сөздігі мен матрица іздеу бағытын анықтауға көмектеседі. Матрица балдары диагноз ықтималдығын білдірмейді.
5. Сервер JSONL файлынан дайындалған индекстен хаттама үзінділерін іздейді, жас пен жынысқа сәйкестігін ескереді.
6. Модель қатысты үзінділерді таңдайды. Жауаптың дереккөзге сәйкестігі, сандары және қауіпсіздік талаптары тексеріледі.
7. Орысша жауапта түпнұсқа үзінділері көрсетіледі. Қазақша және ағылшынша аударма қосымша тексеріледі.
8. Жауап астына сервер тексерген дереккөз сілтемелері қосылады. Расталмаған жауап көрсетілмейді: жүйе нақтылау сұрағын немесе дәрігерге қаралуды ұсынады.

Қазіргі жүйе жеке оқытылған медициналық модель емес: дайын тілдік модель, хаттамалық іздеу және серверлік тексерулер бірге жұмыс істейді. MedElement сілтемесі көрсетілгенімен, негізгі жауап көзі — сақталған JSONL экспорты; әр сұрақта сайтты тікелей ашу талап етілмейді.

Архитектураның толық сипаттамасы: [медициналық жұмыс ағыны](docs/medical-workflow.md).

## Жергілікті іске қосу

Node.js пен npm қажет. Хаттама индексін қайта құру үшін Python 3, серверді басқару үшін Supabase CLI қолданылады. Supabase-ты компьютерде толық іске қосу үшін Docker қажет; бұлттағы дайын сервермен жұмыс істейтін фронтендке Docker керек емес.

Барлық команданы `package.json` орналасқан жоба түбірінде орындаңыз.

### 1. Тәуелділіктерді орнату

```bash
npm ci
```

### 2. Фронтендтің орта айнымалылары

Жоба түбіріндегі `.env` файлына өз Supabase жобаңыздың мәндерін енгізіңіз. Бар файлды өзгертпес бұрын оның баптауларын тексеріңіз.

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

`VITE_` айнымалылары браузерге беріледі. OpenAI API кілтін немесе Supabase service-role/secret кілтін оларға жазуға болмайды.

### 3. Сайтты іске қосу

```bash
npm run dev
```

Сайт: [http://localhost:8080](http://localhost:8080).

Фронтенд іске қосылғанымен, медициналық жауап үшін Supabase жобасында дерекқор, `chat` функциясы және хаттама қоймасы бапталған болуы керек.

## Supabase серверін баптау

### Дерекқор

Схема мен қолжетімділік саясаттары `supabase/migrations/` ішінде орналасқан. Жаңа ортаға миграциялар уақыт ретімен қолданылуы керек. Бар ортада бұрын орындалған SQL файлдарын қайтадан қолмен орындамаңыз; алдымен миграция тарихын салыстырыңыз.

`20261013090000_medical_workflow_audit.sql` миграциясы медициналық тексеру журналын сақтауға арналған `medical_audit` бағанын қосады.

### Сервер құпиялары

Supabase Dashboard → Edge Functions → Secrets бөлімінде баптаңыз:

| Айнымалы | Мақсаты |
| --- | --- |
| `OPENAI_API_KEY` | Серверден OpenAI API шақыру |
| `PROTOCOL_FILES_BASE_URL` | Дайын хаттама файлдары орналасқан мекенжай |
| `OPENAI_MODEL` | Қажет болса, ортақ модельді өзгерту |
| `OPENAI_FREE_MODEL` | Қажет болса, Free режимінің моделін өзгерту |
| `OPENAI_PRO_MODEL` | Қажет болса, Pro режимінің моделін өзгерту |

Supabase қызметтік айнымалылары сервер ортасынан алынады. Нақты құпияларды README, код, скриншот немесе Git репозиторийіне қоспаңыз.

### Функцияны жариялау

```bash
npx supabase login
npx supabase functions deploy chat --project-ref YOUR_PROJECT_REF
```

`YOUR_PROJECT_REF` орнына өз жобаңыздың идентификаторын жазыңыз. Команданы жоба түбірінен орындаңыз, әйтпесе `supabase/functions/chat/index.ts` табылмайды.

### Жергілікті Edge Function

`supabase/functions/.env.example` үлгісінен `supabase/functions/.env` жасаңыз. OpenAI кілтін және хаттама мекенжайын толтырыңыз. Docker ішінен жергілікті Vite серверіне қатынау мысалы:

```env
PROTOCOL_FILES_BASE_URL=http://host.docker.internal:8080/protocol-search/
```

```bash
npx supabase start
npx supabase functions serve chat --env-file supabase/functions/.env
```

Жергілікті серверді қолданғанда фронтендтің Supabase URL және publishable/anon кілті де сол жергілікті ортаға сәйкес болуы керек.

## Хаттамаларды дайындау және жүктеу

Жинақта 1 187 клиникалық хаттама бар. Нақты мазмұн қолданылған экспорт нұсқасына тәуелді.

Бастапқы файлдың әдепкі орны:

```text
data/medelement_export/protocols_mz_rk.jsonl
```

Толық архив Git-ке қосылмайды. Экспортты осы орынға қойып, индексті жасаңыз:

```bash
npm run protocols:build
npm run protocols:test
```

Басқа папкадағы JSON немесе JSONL үшін:

```bash
python -X utf8 scripts/build_mz_protocol_files.py --source "PATH_TO_EXPORT/protocols_mz_rk.jsonl"
```

Дайын іздеу файлдары `public/protocol-search/` папкасына жазылады. Серверге сол папканың толық мазмұны, соның ішінде манифест пен архитектура файлдары қажет.

Жеке Supabase Storage қоймасына жүктеу:

```bash
python -X utf8 scripts/publish_protocol_storage.py --project-ref YOUR_PROJECT_REF --configure
npx supabase functions deploy chat --project-ref YOUR_PROJECT_REF
```

Жүктеу скрипті CLI авторизациясын пайдаланады, `medical-protocols` bucket-іне жаңа нұсқаны жүктеп тексереді және `--configure` берілсе, файл мекенжайын серверге орнатады. Нәтиже `protocol-storage-deployment.json` файлына жазылады.

Баламасы: файлдарды статикалық хостингте жариялап, `PROTOCOL_FILES_BASE_URL` мәнін `https://YOUR_SITE/protocol-search/` мекенжайына бағыттау. Жарияламас бұрын бастапқы материалды тарату құқықтарын тексеріңіз.

## Тексеру командалары

```bash
npm test
npm run medical:test
npm run protocols:test
npx tsc --noEmit -p tsconfig.app.json
npm run build
```

| Команда | Не тексереді? |
| --- | --- |
| `npm test` | Диалог, жауаптарды тану, дереккөздер және компоненттер |
| `npm run medical:test` | Медициналық ағын, шұғыл бағыттау, қауіпсіздік шектеулері |
| `npm run protocols:test` | Хаттамалық файлдар мен іздеу |
| `npm run build` | Жариялауға арналған фронтенд жинағы |
| `npm run preview` | Жиналған фронтендті алдын ала қарау |

Бұлттағы сервердің дайындығын тексеру:

```bash
python -X utf8 scripts/check_deployed_medical_backend.py --project-ref YOUR_PROJECT_REF
```

Синтетикалық диалогпен нақты AI сұрауын тексеру:

```bash
python -X utf8 scripts/check_deployed_medical_backend.py --project-ref YOUR_PROJECT_REF --probe-workflow information --language ru
```

`--probe-workflow` OpenAI API сұрауларын орындайды және шығын тудыруы мүмкін. Тексеру пациент чатына жазылмайды. Скрипт уақытша тексеру токенін баптайтындықтан, мұндай тексерулерді қатар емес, кезекпен іске қосыңыз.

## Жариялау

1. Supabase миграциялары мен сервер құпияларын баптаңыз.
2. Хаттама индексін дайындап, серверге қолжетімді қоймаға жүктеңіз.
3. `chat` Edge Function функциясын жариялаңыз.
4. `npm run build` арқылы фронтендті жинаңыз; нәтиже `dist/` ішінде болады.
5. Хостингте React Router жолдары үшін `index.html` бетіне SPA fallback орнатыңыз.
6. Жүйеге кіруді, хаттамалық жауапты, дереккөз сілтемесін және сервер күйін тексеріңіз.

Фронтенд пен Edge Function бөлек жарияланады. `npm run build` сервердегі AI логикасын жаңартпайды.

## Шектеулер

Экспорт автоматты түрде алынған: хаттамалардың өзектілігі мен клиникалық дұрыстығы тәуелсіз түрде расталмаған. Суреттердегі OCR арқылы алынбаған мәтін және экспортқа енбеген PDF мазмұны іздеуде болмауы мүмкін. Тесттердің өтуі клиникалық валидацияны білдірмейді.

Жүйе чат арқылы нақты диагноз қоймауға, жеке дәрі мөлшерін тағайындамауға және расталмаған медициналық мәтінді көрсетпеуге арналған. AI қателесуі мүмкін; медициналық шешімдер үшін дәрігердің бағалауы қажет.
